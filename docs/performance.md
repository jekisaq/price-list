# Замеры больших файлов

Замер выполнен **27.10.2026**, 07:04 по Екатеринбургу (02:04 UTC).
[Исходный JSON](validation/performance-2026-10-27.json) содержит параметры среды,
бюджеты и значения каждого измерения. Команда воспроизведения:

```powershell
npm.cmd ci
npm.cmd run test:performance
```

Система: Windows 11, `10.0.26200`, x64; AMD Ryzen 5 7500F, 6 ядер / 12 логических
процессоров, 32 ГиБ RAM. Electron 45.0.0, Chromium 156.0.8078.48, встроенный
Node.js 24.22.0. Использованы production-ресурсы electron-vite под Electron
тестовым сценарием; системные диалоги подменены. Это не замер чистой Sandbox
и не отдельный benchmark NSIS-установки.

## Результат одного прогона

| Показатель | CSV: 100 000 товаров | XLSX: 25 000 товаров | Бюджет |
| --- | ---: | ---: | ---: |
| Импорт → расчёт → страница отчёта → экспорт | 576 мс | 382 мс | 10 000 / 15 000 мс |
| Максимальный интервал таймера main | 21 мс | 25 мс | <250 мс |
| Максимальный интервал таймера renderer | 13.8 мс | 11 мс | <250 мс |
| Измеренная куча worker | 73.2 МиБ | 113.0 МиБ | <512 МиБ |
| RSS main вместе с worker | 273 МиБ | 310 МиБ | <900 МиБ |
| JS-куча main | 17 МиБ | 17 МиБ | <128 МиБ |
| JS-куча renderer | 9.54 МиБ | 9.54 МиБ | <128 МиБ |

В обоих случаях импорт, обработка и экспорт сохранили все товары; проверен
последний артикул с ведущими нулями. Импорт вернул только 100 строк предпросмотра,
а расчёт — сводку без полных массивов товаров. Запрос страницы на 500 000 строк
отклонён. В отчёте на странице 200 строк отрисовано 18 строк данных; прокрутка
дошла до записей за пределами первой сотни.

Отдельно тот же тест импортирует CSV на 400 000 товаров через UI, подтверждает
отмену, проверяет недоступность старого результата и успешно обрабатывает новый
небольшой файл. Время отменённой операции не входит в таблицу выше.

## Что именно измерено

Данные синтетические: три колонки, восьмизначный строковый артикул, русское
наименование, цена 10.25. Наценка 20%. XLSX генерируется ExcelJS. Создание
исходных файлов и запуск окна происходят до начала таймера. В измерение входит
чтение, обработка, страница из конца отчёта и запись результата в том же формате,
а также небольшой запрос проверки лимита страницы. Диалоги не требуют человека.

Таймеры с периодом 10 мс измеряют **интервал между вызовами**, а не чистую задержку
сверх 10 мс. RSS и куча main считываются выборочно таймером; куча worker приходит
с событиями прогресса. Куча renderer берётся из `performance.memory` и может быть
округлена Chromium. Это наблюдавшиеся максимумы выборок, не точные пиковые
значения всех процессов. GPU и отдельные renderer-процессы не включены в RSS main.

Один прогон не даёт медиану, p95 или гарантии для чужого компьютера. Кэш диска не
сбрасывался; фоновые приложения не контролировались. Сравнивать CSV и XLSX по
этим числам как одинаковую нагрузку нельзя: отличаются число строк и формат.
Сложные книги, длинные поля и большое число колонок потребляют больше ресурсов.
Для рабочего файла соблюдайте лимиты из [инструкции](user-guide.md).

Новый прогон записывает `out/tests/performance.json`. Чтобы обновить опубликованные
цифры, сохраните новый JSON в `docs/validation/` и согласованно обновите эту
таблицу и README. Тест завершится ошибкой при нарушении заданных бюджетов.

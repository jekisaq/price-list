# Проверка Windows-релиза

Цель: Windows 10/11 x64, обычный пользователь, без Node.js, npm, Excel и исходников.
Версия берётся из `package.json` (сейчас 1.0.0), название — Price List,
идентификатор — `com.price-list.desktop`.

## Автоматические проверки на машине сборки

```powershell
npm.cmd ci
npm.cmd run samples
npm.cmd test
npm.cmd run test:smoke
npm.cmd run test:performance
npm.cmd run test:packaged
npm.cmd run dist
```

| Проверка | Что подтверждает |
| --- | --- |
| `test` | Нормализация, обязательные поля, дубли, точная наценка/округление, импорт/экспорт, ошибки записи, профили, отмена и очистка worker |
| `test:smoke` | Интерфейс → preload → IPC → worker, сопоставление, отчёт, CSV/XLSX, повторное открытие XLSX, восстановление после ошибок, профили в отдельных запусках |
| `test:performance` | CSV 100k / XLSX 25k, память/время, страницы и виртуализация, подтверждённая отмена большого импорта и новый импорт после отмены |
| `test:packaged` | Настоящий `release/win-unpacked/Price List.exe`, production preload и worker в ASAR, экспорт и повторный импорт обоих форматов, сохранение профиля после нормального закрытия и запуска |
| `dist` | Создание NSIS x64 установщика с названием, версией, ярлыками и собственной иконкой |

`test:packaged` включает локальные отладчики только аргументами тестового запуска.
До исполнения main задаётся отдельная папка `out/tests/packaged-*/user-data`.
Файлы пользователя не используются; диалоги подменяются через отладчик для
записи только в эту тестовую папку. В production нет тестовых IPC или режима обхода
проверок. Результат запуска записывается в `out/tests/packaged-*/result.json`.
Можно проверить уже собранную или установленную копию:

```powershell
node --experimental-strip-types tests/packaged.smoke.ts "C:\path\to\Price List.exe"
```

Для этой автоматизации Node.js нужен на тестовой машине; само приложение его
не требует. Сборка включает только `out/main`, `out/preload`, `out/renderer`,
production-зависимости, метаданные и иконку. Тесты и большие примеры не упаковываются.

## Автоматический прогон в Windows Sandbox

После включения компонента «Песочница Windows» и перезагрузки выполните из корня:

```powershell
.\scripts\start-windows-sandbox.ps1
```

Нужен уже собранный `release/Price-List-1.0.0-x64-Setup.exe`. Сценарий создаёт
новую Sandbox с отключённой сетью. Гость получает только установщик, небольшие
CSV/XLSX и PowerShell-сценарий; исходники, Node.js, npm и Excel не передаются.
Входная папка доступна только для чтения, отдельная папка результатов — для записи.
Проверка не устанавливает приложение на основной компьютер.

`scripts/windows-sandbox.ps1` проверяет SHA-256, тихую установку NSIS для текущего
пользователя в путь с пробелами и кириллицей, ярлыки, версию и запись удаления.
Затем запускает установленный EXE, импортирует CSV/XLSX, рассчитывает наценку,
экспортирует оба формата, повторно читает результаты и проверяет профиль после
закрытия и запуска. В конце запускает деинсталлятор и проверяет удаление EXE,
ярлыков и записи реестра, сохранность профиля и экспортированных файлов.

Журнал, сведения об ОС/правах, снимок renderer, экспортированные файлы и итоговый
`result.json` сохраняются в `out/tests/windows-sandbox-*/results/`.
`passed: true` означает успешное завершение всех проверок сценария.

Это автоматический тест: установка и удаление выполняются с `/S`, диалоги выбора
файла подменяются через локальный отладчик только на время тестового запуска.
Используется штатная учётная запись Sandbox; её права записываются в отчёт.
Проверка мастера установки, нативных диалогов, SmartScreen и обычного пользователя
без прав администратора остаётся отдельным ручным прогоном.

## Дополнительный ручной прогон

Сборка и тест исполняемого файла на машине разработчика не подтверждают установку
и удаление на чистой Windows. Используйте новую VM / Windows Sandbox без среды
разработки. Для проверки сохранения профиля перезапускайте приложение внутри той
же сессии Sandbox; закрытие Sandbox уничтожит её диск.

Передайте туда `release/Price-List-1.0.0-x64-Setup.exe` и папку `samples/`;
большие примеры заранее создайте командой `npm run samples` на машине сборки.
Не передавайте папку проекта или `node_modules`. Сверьте SHA-256 установщика
между исходной машиной и VM через `Get-FileHash -Algorithm SHA256`.

1. Войдите обычным пользователем. Запустите установщик, выберите установку для
   текущего пользователя и путь с пробелами/кириллицей. Проверьте название,
   версию, иконку, ярлыки рабочего стола/меню «Пуск» и запись в списке приложений.
2. Запустите приложение ярлыком без терминала и сети. Импортируйте
   `csv/supplier-basic.csv` (UTF-8, запятая, заголовок 1). Проверьте 10 товаров,
   сопоставление русских колонок, артикул `001` и цену 144.00 при наценке 20%.
3. Экспортируйте CSV и XLSX в папку с кириллицей. Снова откройте каждый результат:
   10 товаров, колонки «Артикул», «Наименование», «Цена», артикул `001`, цена 144.
   Для проверки без повторной наценки выставьте наценку 0%.
4. Откройте `xlsx/supplier-basic.xlsx`, лист «Товары». Проверьте 3 товара,
   артикул `000001`, кириллицу и числовую цену. Откройте оба примера с ошибками:
   экспорт блокируется, отчёт содержит исходные строки и причины.
5. Проверьте `supplier-duplicates`: ручной режим, затем «первая» и «последняя».
   Цена для `001` соответственно 12.00 и 24.00 при 20%; без подтверждения пропуска
   исключённых строк экспорт недоступен.
6. Сохраните профиль с названием «Поставщик — проверка», параметрами CSV,
   сопоставлением и наценкой 25%. Закройте приложение обычным крестиком,
   запустите снова и проверьте восстановление профиля и параметров нового импорта.
7. Импортируйте CSV 400k; остановите импорт через подтверждение. Повторите для
   расчёта и экспорта большого файла, затем обработайте обычный пример.
   При отмене экспорта существующий файл должен сохраниться, временные
   `.price-list-*.tmp` рядом с назначением должны отсутствовать.
8. Отмените выбор/сохранение файла; попробуйте экспорт в недоступную для записи
   папку и файл, занятый другим приложением. Проверьте понятные сообщения,
   сохранность старого файла и успешное повторение в доступную папку.
9. Закройте приложение и удалите его через «Установленные приложения».
   Проверьте удаление исполняемых файлов, ярлыков и записи деинсталляции.
   Экспортированные файлы и профили должны сохраниться: удаление не стирает
   пользовательские данные. Для сброса теста удаляйте только тестовый профиль
   Windows или восстановите снимок VM.
10. Установите ту же версию заново: профиль должен восстановиться. Зафиксируйте
    версию/сборку Windows, права пользователя, путь, SHA-256 установщика,
    результаты каждого пункта и ошибки/снимки экрана.

Релиз пока не подписан: автоматическая подпись требует сертификата издателя.
При ручном прогоне отдельно зафиксируйте поведение SmartScreen для этого файла.
